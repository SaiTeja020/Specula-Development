# Local build and validation

Use [local runtime and recovery](local_remediation.md) for access policy and durable checkpoints. Local deployment requires the ignored authentication configuration generated by `scripts/configure_local_runtime.py`.

## Repeatable commands

The datastore monitors and knowledge graph refresh every 10 seconds while visible and support manual refresh. Quickwit/Chroma metrics come from current stores; DuckDB holds saved analytics snapshots and FAISS holds the shared versioned reference corpus. Chroma persists in the `specula-chroma-data` named volume at `/data`; its image is pinned to the verified digest. Do not reset this volume during boot. The legacy `data/chromadb` directory is not the current database. Historical indexing receipts are not evidence that those vectors still exist; mismatches are shown in the case monitor.

Run from the repository root in PowerShell:

```powershell
docker compose up -d kafka schema-registry redis quickwit neo4j chromadb redpanda-console
# Build once after dependency changes; this installs ReportLab into the shared image
# and verifies actual PDF generation before the image is accepted.
docker compose -f docker-compose.yml -f docker-compose.local.yml build hitl-api
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --no-build hitl-api visualizer-api dfkg-consumer
.\venv\Scripts\python.exe scripts/check_environment.py
.\venv\Scripts\python.exe scripts/validate_progress.py
.\venv\Scripts\pytest.exe -m integration tests/integration/test_case_investigation_e2e.py -q -p no:cacheprovider --basetemp=.pytest-tmp-case-run
$env:SPECULA_LLM_BACKEND='stub'
$env:SPECULA_THREAT_ATTRIBUTION_BACKEND='stub'
.\venv\Scripts\pytest.exe tests/agents tests/ingestion tests/test_skeleton_graph.py tests/test_visualizer_api.py tests/test_visualizer_api_db.py tests/test_visualizer_ws.py -m 'not live_infra and not integration' -q -p no:cacheprovider --basetemp=.pytest-tmp-unit-run
```

Use a fresh temporary directory name for overlapping test runs. The verification fixture intentionally retains labeled validation evidence, graph nodes, Chroma records and Kafka topics; it never deletes unrelated data. Latest machine evidence is `data/verification/local_case_latest.json`.

Frontend commands (installed dependencies already present):

```powershell
Set-Location visualization
npm run build
.\node_modules\.bin\vite.cmd --host=127.0.0.1 --port=5173
```

API: `http://localhost:8300`; frontend: `http://localhost:5173`. Select an ingested case in Live Investigation. Backend access remains authenticated and case-scoped.

## Validation boundaries

Use labeled synthetic fixtures for verification. Component and fixture checks do not establish production load capacity, whole-system recovery or forensic model quality. See [operations runbook](operations_runbook.md) for production gates and [local model testing](local_model_testing.md) for the local Ollama/no-billable-GCP boundary.
